ER模型(图)的基本概念、设计方法与工具详述

前言

数据库设计过程的一个主要部分是决定如何在设计中表示各种类型的“事物”，而E-R模型(Entity-Relationship Model，实体-联系模型)被开发来方便数据库的设计[1]，最早由最早由Peter Chen（陈品山）于1976年提出[2]。E-R模型将现实世界的概念、含义与交互映射到概念模式，在现实世界与计算机之间搭建起了一个可靠的桥梁，大大方便了数据库的设计。E-R模型的图形表示称作E-R图，如今E-R图的使用已经非常普遍，相关的快速生成工具也是一堆堆的。

本文将先主要介绍E-R模型主要的基本概念并给出对应E-R图的表示，随后用一个具体的例子来介绍如何设计一个数据模型并得出最终的E-R图，最后介绍一些E-R图绘制的相关工具。

注意E-R模型与E-R图的关系，E-R模型相当于是一个规则、概念的描述集合，E-R图相当于是这个集合的可视化。举个例：假设E-R模型分别有一个老师和一个学生的概念，E-R图把这个概念表示出来，那就用一个方框表示一个老师，用一个圆圈表示一个学生。实际使用时，两者几乎是同时进行的，也就是想一点画一点。

正文

一、E-R模型在数据库设计中的角色定位

数据库设计可以简要概括为四个阶段[3]：

  • 数据需求获取阶段：了解数据需求，整理需求规格说明文档；
  • 概念设计阶段：选择一种数据模型，并采用所选数据模型的概念将这些需求转化为数据库的概念模式。这些概念模式负责描述整理出的数据需求。用实体-联系模型的术语来说，概念模式明确规定了数据库中表示的实体、实体的属性、实体之间的联系，以及实体和联系上的约束。通常，概念设计阶段会导致实体-联系图的构建，它提供了对模式的图形化表示；
  • 逻辑设计阶段：将高层概念模式映射到将被使用的数据库系统中，并使用具体的数据结构表示。例如使用关系型数据库中的表来表示数据模型；
  • 物理设计阶段：决定数据库的硬件支持。

可以看出，E-R模型实际处于概念设计阶段，使用E-R模型与E-R图，我们能很方便地定义以及表示实体、实体的属性、实体之间的联系，以及实体和联系上的约束。如今E-R模型几乎必定会出现在概念设计阶段，而E-R模型的广泛使用在很大程度上可能与E-R图简单而清晰的特性有关。

注意E-R Model(Entity-Relationship Model)一般翻译为实体-联系模型，而不是实体-关系模型。在数据库和概念建模领域，“联系”和“关系”是有精确区分的，“联系”描述了业务里实体之间怎么互相关联，而“关系”描述了数据如何被组织存放（且特指关系型数据库的数据组织方式）。

所以E-R模型并非关系型数据库专属，而是可以用于所有数据库，不过实际效果各有不同。而E-R图实际上天生与关系型数据库最为契合。

二、基本概念

E-R模型有三个基本概念：实体集、联系集和属性[4]。E-R图中用矩形表示实体集，用菱形表示联系集，用椭圆表示属性。

注意本章节的E-R图表示使用的是Peter Chen最初提出画法，名为陈氏表示法，但是该版的E-R图有一定局限性（当关系复杂时，该表示法可能变得杂乱），优点是简单易理解。后续在此基础上有人提出了Crow’s foot(乌鸦脚)方法来画E-R图[5]。两者具体的规则见附录1:陈氏表示法与乌鸦脚表示法示意图。

注：实际上好像也没有一个类似“国标”的标准，怎么方便就怎么画。

2.1 实体集

一个实体(entity)是现实世界中可区别于所有其他对象的一个“事物”或“对象”，例如一个学生、一辆车都可以是一个实体。每个实体通过一组属性(attribute)表示，属性是实体集中每个成员所拥有的描述性性质，在本章第小3节中会介绍更多关于的属性概念。实体中的某些性质集合的值必须唯一，该值用于唯一标识这个实体，例如一个学生的学号属性可用于唯一标识这个人，这个属性可被称作主键(key)。实体集(entity set)是共享相同属性、具有相同类型的实体的集合。用E-R图表示一个学生实体集示例如下：

2.2 联系集

联系(relationship)是指多个实体间的相互关联。例如可以在多个学生和一个老师之间定义一个“教学”联系，这一联系表明这个老师负责教授这些学生。联系集(relationship set)是相同类型联系的集合。映射基数(mapping cardinality)表示一个实体能通过一个联系集关联的另一些实体的数量。映射基数在描述二元联系集(即该联系只负责描述两个实体)时最有用，尽管它们可用于描述涉及多于两个实体集的联系集。 对于实体集A和B之间的二元联系集R来说，映射基数必然是以下情况之一：

  • 一对一（one-to-one）。A中的一个实体至多与B中的一个实体相关联，并且B中的一个实体也至多与A中的一个实体相关联（如图2.2左所示）

  • 一对多（one-to-many）。A中的一个实体可以与B中任意数量（零个或多个）的实体相关联，而B中的一个实体至多与A中的一个实体相关联（如图2.2右所示）

  • 多对一（many-to-one）。A中的一个实体至多与B中的一个实体相关联，而B中的一个实体可以与A中任意数量（零个或多个）的实体相关联（如图2.3左所示）

  • 多对多（many-to-many）。A中的一个实体可以与B中任意数量（零个或多个）的实体相关联，而且B中的一个实体也可以与A中任意数量（零个或多个）的实体相关联（如图2.3右所示）

例如老师可以教学很多学生，学生也可以被多个老师教学，所以是多对多的映射基数。使用E-R图表示老师与学生联系的示例图如图所示(为方便下图简化了属性)：

另外，联系集也能有属性。实体集的属性描述了实体自己是什么，而联系集的属性描述了实体之间联系的细节，例如：学生与课程之间有一个选课联系，而学生选课是为了得到课程成绩并最终得到学分，那么这个联系就可以有成绩、学分两个属性。联系集的属性使用虚线连接，E-R图示例如下：

虽然E-R模型里有联系集与关联实体的概念，实际在概念设计阶段好像都没怎么用这玩意儿？都是一律用联系集表示就行了。而在逻辑设计阶段，例如关系型数据库都会将其提升为关联实体，并为其设计一张中间表来存这个关联实体，为其赋予业务意义与属性。

2.3 属性

属性是实体集中每个成员所拥有的描述性性质。按照不同侧重点，可以将属性按照三种不同类型方向描述：

  • 简单(simple)属性与复合(composite)属性。简单属性是指哪些不能被进一步划分为子部分的属性，而复合属性是指可以被进一步划分为子属性的属性。例如名字属性可以划分为姓属性与名属性。E-R图中使用多级连接方式来表示复合属性，如图2.7(a)示例，为方便图中省略了其他属性，下同；
  • 单值(single-valued)属性与多值(multivalued)属性。如果一个属性取值只能有一个，那么称这个属性为单值属性，若能取多个值，则称该属性为多值属性。例如一个学生的学号的取值只能有一个，该属性为单值属性，但是一个学生的手机号能够有多个取值，该属性为多值属性。E-R图中使用双线椭圆表示多值属性，如图2.7(b)示例；
  • 派生(derived)属性。如果一个属性的取值是由其他相关属性或实体集中派生而来，那么该属性则称之为派生属性。例如一个学生有多个老师，那么可以从这两个实体集中派生出一个老师数量属性，表示学生的有多少个老师，又如学生有一个出生日期属性，则可以通过此属性派生出一个年龄属性，年龄属性的值根据出生日期计算得到。E-R图中使用虚线椭圆表示一个派生属性，如图2.7(c)示例。

对于关系型数据库，实际很少直接使用复杂的属性(如复合属性、多值属性)。对于复合属性，都会直接将其展开作为简单属性，用多个新列来存储这些简单属性；对于多值属性，一般会直接新开一行来存储不同的值，即不同值对应不同实体，而不是用类似于：phone_num:{"1","2","3"}的形式存储。

本章节只介绍了一些E-R模型中实用的基本概念，还有一些E-R模型中的其他概念例如递归联系集、弱实体集等，虽然这些概念的思想十分重要，但是因为其对应的E-R图表示并没有这么方便明了，所以实际上都是使用其他方法来替代这些概念设计。平时用得最多的还是实体集、联系集与简单属性三者组合，就足够应付简单的概念设计了，对于一些复杂的业务，陈氏表示法的E-R图已经不行了，甚至连E-R模型本身也不够用了（其实本质还是E-R图不够用😶‍🌫️），都是使用大杂烩，啥都用点。

三、从设计 E-R 模型到绘制 E-R 图实战

前面已经介绍了E-R 模型中的核心元素：实体集（Entity Set）、联系集（Relationship Set）、属性（Attribute）与基数约束（Mapping Cardinality）。下面通过一个完整案例，演示如何从现实需求一步步抽象出 E-R 模型，并最终绘制 E-R 图。

3.1 需求分析

假设现在需要设计一个“学生选课系统”，业务需求：①学生可以选修多门课程；②一门课程也可以被多个学生选修；③学生具有：学号、姓名、性别；④课程具有：课程号、课程名。通过这些需求，我们需要分析：

  • 哪些是实体；
  • 哪些是实体之间的联系；
  • 各实体有哪些属性；
  • 实体之间是什么基数关系。

3.2 识别实体集（Entity Set）

首先分析现实世界中“能够独立存在”的对象。本案例中：学生（Student）表示系统中的学生对象，课程（Course）表示系统中的课程对象。因此我们得到两个实体集：Student、Course

3.3 识别属性（Attribute）

Student 实体属性：

属性 含义
student_id 学号
name 姓名
gender 性别

其中：student_id用于唯一标识学生。

Course 实体属性：

属性 含义
course_id 课程号
course_name 课程名称

其中：course_id用于唯一标识课程。

3.4 识别联系集（Relationship Set）

学生与课程之间存在：“选课”关系。因此可以得到联系集：Student —— Select —— Course

四、相关 E-R 图绘制工具介绍

随着数据库设计与系统建模的发展，出现了大量专业 E-R 图绘制工具。这些工具不仅支持绘制 E-R 图，还能：

  • 自动生成数据库表结构；
  • 自动分析外键关系；
  • 正向/逆向工程；
  • 导出 SQL；
  • 同步数据库结构；
  • 团队协作建模。

下面介绍几款常见的 E-R 图工具。

1. PowerDesigner

①特点

PowerDesigner 是经典的数据建模工具，在传统企业开发中使用非常广泛。

支持：

  • Chen E-R 图
  • 乌鸦脚表示法
  • UML
  • 数据库正向工程
  • 数据库逆向工程

适合：

  • 企业级数据库设计
  • 大型项目建模
  • 数据仓库设计

②优点

  • 功能非常强大；
  • 建模规范完整；
  • 支持多种数据库；
  • 工业界认可度高。

③缺点

  • 学习成本较高；
  • 软件较重；
  • 界面偏传统。

2. MySQL Workbench

①特点

MySQL 官方数据库设计工具。

支持：

  • 乌鸦脚 ER 图
  • 表关系设计
  • SQL 自动生成
  • 数据库同步

非常适合：MySQL 学习与中小型项目设计。

②优点

  • 免费；
  • 与 MySQL 集成度高；
  • 上手简单；
  • 非常适合初学者。

③缺点

  • 对复杂建模支持一般；
  • 更偏数据库实现层。

3. Navicat

①特点

除了数据库管理外，也支持：

  • 数据库关系图；
  • 自动 E-R 图生成；
  • 表结构可视化。

适合：

  • 日常开发；
  • 快速查看数据库结构。

②优点

  • 界面友好；
  • 操作简单；
  • 开发体验好。

③缺点

  • 建模能力不如专业工具；
  • 更偏数据库管理工具。

4. Visual Paradigm

①特点

支持：

  • UML
  • E-R 图
  • BPMN
  • 系统架构图

是一款综合性建模工具。

②优点

  • 支持多种建模规范；
  • 图形界面现代；
  • UML 与数据库建模结合较好。

③缺点

  • 部分高级功能收费；
  • 功能较多，上手需要时间。

5. 在线 E-R 图工具

近年来，在线绘图工具越来越流行，例如：

  • draw.io
  • Lucidchart
  • ProcessOn

这些工具：

  • 无需安装；
  • 支持协作；
  • 适合快速绘图。

对于学习、博客、教学与小型项目非常方便。
